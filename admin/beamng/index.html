ASAAAB.COM · PIT CREWBeamNG Playbook

How the production desk drives BeamNG.drive by itself: the rules, the console tricks, the capture pipeline, and every way it broke. Written after the night the 9-3X doors finally opened.

Golden rules

Never "open application" on Beam while it's running. It launches a second copy and crashes the first (0xC0000409). It cost us a staged scene once. Bring Beam forward by clicking its taskbar icon.
Don't touch Beam's files while the game is running. No mods, no user folder, no reads either.
Never press J unless asked. If you need a pause, do it from Lua (below) so you know exactly when it happened.
Look before you ask. Take a screenshot instead of asking what's on screen.
Leave the UI visible. Alt+U hides the console and the pause menu too, so you lose track of state. Crop the UI out of the frame instead.

The console is the steering wheel

Everything reliable happens in the GE Lua console (key `, grave). It is sandboxed but has be, core_camera, commands, core_jobsystem, simTimeAuthority and queueLuaCommand into the car.

Typing into it

  • Type key by key. Clipboard paste gets eaten by focus thieves (the Claude window, Textinputhost, Discord).
  • After opening the console, click the input twice (~0.4 s apart). The first click often doesn't take focus.
  • Keep each command under ~250 characters. Split long ones, or store a string in a global and use it in the next command.
  • Before you hit Return, zoom on the input line (y≈605–625) to confirm the text actually landed.
  • The log does not auto-scroll. Don't treat a missing line as proof that a command didn't run. Check the game view instead.

Frame recipe (one console command)

Click sky (700,100) → ` → wait 1 → click input ×2 → BackSpace×10 → type → Return → wait 0.5 → ` → wait 1.5 → capture.

Helpers to type once per session

-- car anchor + rotate-in-place (NOTE: this teleport RESETS the car: doors close, damage clears)
TT=be:getPlayerVehicle(0):getPosition() function R(d) local a=math.rad(d)/2 be:getPlayerVehicle(0):setPositionRotation(TT.x,TT.y,TT.z,0,0,math.sin(a),math.cos(a)) end

-- free camera at an offset from TT, heading h (degrees). h=-90 looks along -x.
commands.setFreeCamera()
function C(dx,dy,dz,h) local a=math.rad(h)/2 core_camera.setPosition(0,vec3(TT.x+dx,TT.y+dy,TT.z+dz)) core_camera.setRotation(0,quat(0,0,math.sin(a),math.cos(a))) end

-- orbit shot k of 24 (15 deg steps) around the car centre; k=0 driver side, 6 nose, 12 passenger, 18 tail
function O(k,r) r=r or (k==17 and 4.55 or 5.2) local p=math.rad(-15*k) C(0.5+r*math.cos(p),0.24+r*math.sin(p),1.1,-90+15*k) end
K=0 function N2() O(K) K=K+1 end     -- then each frame is just: N2()

Doors, hood, trunk (no clicking needed)

-- open EVERYTHING (doors + hood + tailgate): toggles every coupler group
be:getPlayerVehicle(0):queueLuaCommand("for k,v in pairs(controller.getAllControllers()) do if k:find('oupler') then v.toggleGroup() end end")
-- driver door only: add  k:find('FL') and  to the if

Freeze the moment

-- reset, open, wait for the doors to swing, then pause physics (doors swing shut on their own otherwise)
R(0) K=0 O(0) core_jobsystem.wrap(function(j) j.sleep(3) be:getPlayerVehicle(0):queueLuaCommand(Q) j.sleep(1.2) simTimeAuthority.pause(true) end)()
simTimeAuthority.pause(false)   -- unpause

Timers without the console

core_jobsystem.wrap(function(j) … j.sleep(6) … end)() runs a background script. That means one console command can drive a whole sequence.

Reading values out

guihooks.message(text, seconds, id) shows a toast (it's clipped at the right edge on this monitor). Vehicle-side log('I','ZZ',x) lands in the console log.

Turntable capture pipeline

  1. Orbit the camera, not the car. setPositionRotation resets the vehicle, which re-latches the doors. Moving the camera leaves the physics alone, so open doors stay open.
  2. Shoot the closed set: R(0) K=0, then N2() ×24.
  3. Run the reset → open → pause job, then N2() ×24 for the open set. Then the driver-door job, then O(23) O(0) O(1).
  4. Capture with zoom, not screenshot: region [385,200,1225,565] at scale 0.6 → 941×409. Full screenshots of the busy Utah scenery fail as "too large".
  5. No more than ~8 images per batch; 4 frames per batch is the sweet spot.
  6. Check every frame. If the console shows in a capture, the toggle lost sync. Stop before stray keys hit the game.
  7. Resize to 920×400 and save as JPEG quality 84. Files: cNN closed, oNN open, d23 d00 d01 driver door.
The scene is deterministic. R(0) puts the car back in exactly the same spot, so any single frame can be re-shot later and it still matches.

Shipping it

Frames go to assets/turntable/. Upload through the GitHub upload page, wait until all files finish processing before you press Commit (a premature commit silently drops the files), then pull and diff the pixels to verify.
